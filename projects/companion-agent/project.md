## 一句话介绍

一个安静的社交陪伴系统，通过观察用户的输入行为，在真正需要时主动提供沟通建议，而不是频繁打扰。

---

## 问题

### 我观察到的现象

在日常社交场景中，我发现很多人（包括自己）会在这些时刻卡住：

- **面对批评时**：不知道如何既保护自己又不激化矛盾
- **想找人时**：开了对话框又关掉，反复修改开场白
- **表达情绪时**：想说的很多，但打出来又觉得不合适删掉

这些"输入又删除"的行为，背后往往不是因为没话说，而是因为：

1. 不知道如何组织表达
2. 担心说错话让关系变糟
3. 想要回应但找不到合适的语气

### 为什么现有方案不够好

- **聊天机器人**：需要主动召唤，无法在用户犹豫时介入
- **社交技巧课程**：是理论指导，无法在具体场景中实时帮助
- **朋友求助**：不是每次都能找到人，而且会让朋友感到负担

### 我的判断

真正的陪伴，不是一直说话，而是知道什么时候出现。

与其做一个"什么都能聊"的 AI，不如做一个"理解什么时候该出现"的系统。

## 系统如何运行

### 感知层：安静观察

系统通过监听用户的键盘输入，实时计算以下指标：

| 指标 | 计算方式 | 含义 |
|------|----------|------|
| 打字速度 | 字符数 / 输入时长 | 速度变慢 = 认知负荷增加 |
| 删除次数 | backspace 调用频率 | 反复删除 = 犹豫不决 |
| 停顿时长 | 两次输入的间隔时间 | 长时间停顿 = 思考困难 |
| 输入完整性 | 完成发送 / 开始输入 | 高未完成率 = 表达困难 |

### 决策层：四级状态机

```
静默 → 感知 → 试探 → 介入
  ↑      ↓      ↓      ↓
 保持观察  收集信号  准备建议  提供帮助
```

**触发介入的条件**（三选一）：

1. 删除次数 ≥ 3 次 + 已输入内容 > 10 字符
2. 停顿时长 > 12 秒 + 已输入内容 > 5 字符
3. 打字速度 < 1 字符/秒 + 已输入内容 > 10 字符

### 行动层：克制介入

当检测到用户遇到困难时，系统会：

1. **生成建议**：基于当前对话上下文，提供 2-3 种回复选项
2. **温和呈现**：使用小型浮窗，不强制中断用户操作
3. **尊重选择**：用户可以选择"采用"、"下次再问"或"不再提醒"

## 我的工作

### 产品架构

- 设计了感知-决策-行动三层架构，将"什么时候介入"作为核心问题
- 定义了四级状态机（静默/感知/试探/介入），明确每一步的触发条件
- 建立了"软拒绝"机制（本次忽略，下次再问），降低打扰感

### 交互设计

- 界面采用"情绪观察日志"风格，避免过度拟人化
- 实时展示感知指标（打字速度、犹豫指数），让用户理解系统如何判断
- 建议内容包含"AI 分析过程"，增加透明度和可信度

### 技术实现

- 使用 React Hooks 构建输入监听引擎
- 实时计算五维感知指标（打字速度、删除率、停顿时长等）
- 接入豆包大模型 API，实现上下文感知的建议生成
- 本地计算，不上传聊天内容，保护隐私

### 测试与迭代

- 邀请 15 位朋友测试，收集真实场景下的使用反馈
- 调整介入阈值：初始设置过于敏感，收到"频繁打扰"反馈后提高阈值
- 优化建议质量：从"模板化回复"改为"基于上下文的个性化建议"

## 反思

### 如果继续做，下一步会改什么

1. **建议质量**：当前建议还是偏"高情商模板"，需要更多个性化学习
2. **个人习惯学习**：第一周作为校准期，学习用户的说话风格和介入偏好
3. **场景扩展**：除了聊天，还可以应用于邮件回复、论坛发帖等场景
4. **隐私边界**：明确告知用户哪些数据在本地处理，哪些需要调用 API

### 关于商业化的思考

**这是一个有意思的方向，但需要解决几个问题：**

1. **需求验证**：测试反馈显示约 47% 用户愿意长期使用，说明这是一个"有小众需求"而非"刚需"的场景
2. **平台依赖**：作为社交平台的辅助工具，存在被平台政策限制的风险
3. **价值感建立**：用户可能觉得"我自己也能想出来"，需要更强的价值感知

**可能的路径**：

- 作为开发者工具的一部分（代码审查时的沟通建议）
- 作为写作辅助工具（帮助组织思路，而非替用户写作）
- 开源框架，让其他开发者基于此架构构建自己的陪伴系统

**目前结论**：作为概念验证和探索性项目是成功的，但距离商业产品还需要更清晰的价值定位和场景聚焦。
