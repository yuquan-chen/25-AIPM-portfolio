01 / REMEMBER

记住，也留下来源

从第一轮开始，观察声明与原话如何关联。已采纳和待确认分别呈现。

02 / RECALL

换个会话，仍有依据

回到四段会话里的线索，回答一个新的问题。每条记忆都能核对原文和来源。

03 / RESOLVE

遇到冲突，主动说清楚

演示续篇中，规则处理预算冲突，负责人变更交给人工确认。处理结果和历史一起保留。

04剪辑 Agent · 产品原型

剪辑 Agent.

先看一版，再说说感觉。
把每一次修改，接回同一条时间线。

01 / PROPOSE

先把感觉变成提案

把“轻快一点”拆成镜头与时长。确认之前，也可以放慢节奏。

02 / EDIT

每次改动，都看得见

字幕落在具体的秒数，转场出现在镜头交界。轨道与预览同步回应修改。

03 / CONTINUE

第一版之后，继续创作

新想法接回当前版本。加字幕时，保留已经确认的镜头与标题。

05陪伴 Agent · 鹅宝

不是一直说话，
而是知道何时出现。

观察输入中的犹豫，在真正需要时递出建议。

↗DOCUMENT项目说明
鹅宝如何判断是否介入本地交互演示 · 脚本 Mock
十轮脚本演示 · 建议可以采用，也可以忽略10 ROUND SCRIPTED DEMO
01 / SILENT

先保持安静

默认不打断，留给用户自己组织和完成表达的空间。

02 / SENSE

观察输入信号

结合删除、停顿和输入速度，识别犹豫是否持续。

03 / TEST

判断是否需要帮助

对照输入内容与状态变化，避免只凭一次停顿下结论。

04 / OFFER

递出可选建议

达到介入条件后提供轻量建议，选择权仍留给用户。

我做的不是几个彼此独立的 AI 项目，而是一组关于自主性的连续实验：城市可听化让我先把复杂系统变得可感知；Finance Agent 讨论行动边界；Companion Agent 讨论介入时机；Editing Agent 讨论如何在人的确认下继续创作；LLM 学习记录则让我回到模型本身，理解它的能力和不确定性。

我希望做出能运行的产品，也把“什么时候该主动、什么时候该停下”写进产品里。
